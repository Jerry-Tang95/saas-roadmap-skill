# 人效即战略：人效目标 → 生态位 → 自研/合作/组织决策

## R — 原文
> 出处：《主线4 第3节 3.4.2 人效是被动结果还是战略选择》
"深入研究了几家SaaS企业后，我发现人效并不是执行一系列管理动作后所得的被动结果，人效应该是主动的战略选择。"

> 出处：同上，3.4.3 人效目标与生态位
"SaaS企业如果有80万元的人效目标，就不会去做定制开发项目，而是聚焦做产品，做高可配置能力（甚至做PaaS），让代理商、SI公司完成产品在客户侧的落地、交付工作。"

## I — 自述
常识把"人均营收"当考核结果，作者要求把它反过来当自变量：先定人效目标（当年/3年/5年），再让目标倒逼一切做法。逻辑是SaaS的主要成本就是人工成本，人效直接反映经营状况；而目标不同，做法根本不同——同一个业务，20万人效目标下可以派人手搓，80万人效目标下必须改机制。更关键的是人效目标决定生态位：80万人效的公司不做定制开发，聚焦产品和高可配置能力（甚至PaaS），把落地交付让给追求30万人效的代理商/SI；后者靠无法标准化的本地服务建立护城河，平台公司（腾讯约500万人效）天然需要ISV补行业方案。所以人效目标直接回答"做什么、不做什么"。执行用PDCA：P定目标、D在每次决策时找人效更高而效果不差的方法、C季度复盘、A改进。安全边界：除非别人做同样的事人效能达到你的3～5倍，否则不用担心被入侵；产研团队中超过10%的人力在做市面成熟品类即不划算。

## A1 — 书中案例
1. **小鹅通孵化营**（主线4第3节3.4.2）：小鹅通2022年做了多期"孵化营"，每期招募几十名新购客户，含开营直播、录播课、小组作业、结营点评。同是这件事——若人效目标是20万～30万元/年，就为每期安排两个同事全程组织和服务，不影响公司平均人效；若目标是80万～100万元/年，同时开10个营就要20个人，只能改机制：请老学员当组长、让爱表现的同学做指导员、用线上工具自动化机械重复工作，让学员"自治"。作者结论："目标不同，做法不同。"
2. **自研BI还是外部合作**（同上）：客户业务闭环需要一个非核心模块（如BI报表）。作者亲历：自研BI多年后，因为BI不是核心关注点，外部BI产品已经与自研的有了代次差异——自研结果差、人均效率也低。结论：非核心部件不要自研，SaaS的未来是多家产品联合走向市场。
3. **生态位的分层**（3.4.3）：腾讯2021年度人效约500万元（5601亿元÷11.2万人），华为人均产值约326万元（6368亿元÷19.5万人）；腾讯做不到什么都自己做，所以需要千帆计划、SaaS臻选、SaaS加速器，需要ISV补齐行业方案。而代理商/SI追求30万元人效，做本地化开发、个性化交付，这些无法标准化的工作意味着不太高的人效，也意味着平台公司和SaaS产品公司都不能涉足的护城河。
4. **自用系统自研的账**（3.4.4）：纷享销客、销售易各花近10年、5亿元以上研发费用才有今天的CRM。作者粗略评估，多业务类型的企业自用CRM几年下来少不了1000人·月，约折合3000万元——所以"如果产研团队中超过10%的人在做市面上很成熟的产品品类，那是不划算的"。

## A2 — 未来触发 ★
- 场景：①有人介绍一个30万元的定制开发项目，CEO要决定接不接；②产研负责人申请自建BI/报表等"客户要求但非核心"的模块；③公司决定要不要做PaaS、要不要开放给代理商；④年度规划会要定明年人效目标；⑤担心平台公司（钉钉/企微/飞书）入侵自己的赛道。
- 语言信号："这个定制项目接不接"（should we take this custom project / build vs partner）、"我们要不要自己做一个BI"、"定个人效目标吧"（revenue per employee target）、"人效多少算健康"、"平台会不会把我们做了"、"自研还是合作"。
- 与相邻能力的区分：V09管的是"生态位与自研/合作的边界"；如果问题其实是"长期资源该投给谁"，走 V05；如果是"这100万先给哪个部门"，走 V10；如果是"靠提人效来压CAC"，走 V08；如果是"要不要做OP本地部署项目"，作者另有原则（收3倍于SaaS费用、只给标准版）。

## E — 执行步骤
1. **算现状人效**：至少算三个数——全公司人均营收、产研全团队人均产出、销售全团队人均销售额。基准（作者估计，需重新标定）：中国SaaS平均约30万元/人（2021年9月读者群调查），2022年末头部已提升到40万、50万乃至80万元；美国营收过10亿美元的SaaS企业中有一半人均产出超过40万美元。判停：若低于行业均值且现金流吃紧，人效目标优先于营收目标。
2. **定目标并反推做法**（PDCA-P/D）：定当年/3年/5年目标，然后对每项待决策事项问一句"有没有人效更高、效果不差的方法"。判停：若某业务的稳态人效显著低于目标（如定制交付使人均跌到目标生态位之外），该业务不做或交给生态伙伴。
3. **季度复盘并校准边界**（C/A）：每季度统计人效是否达成、策略是否合适。同时检查两条红线——产研团队中做市面成熟品类的人力是否超过10%；是否存在别人做同样事情人效能达到你3～5倍的环节（有则该环节应让渡）。输出：人效目标表＋"自研/合作/外包"决策清单。

## B — 边界
- 不要用：不要把人效当纯考核指标拿来扣奖金（它是战略自变量）；不要用平台公司的人效（腾讯约500万、华为约326万）直接对标创业公司；不要因为追求人效而在验证阶段拒绝打磨产品（验证期靠销售高手单兵突破本就不是为提高营销效率）。
- 作者警告过的失败模式：研发速度跟不上就增人——200人产研团队的产出并不是100人团队的2倍，规模翻倍后可能造成混乱，效率还达不到原来的1.5倍；把产研按"今年销售任务完成比例"考核，会诱导他们接定制项目；为做"一站式解决方案"而什么都自己干。
- 本书的固有局限：写于2022年底—2023年初，作者预测的2024年回暖/2025年IPO已失效；PS倍数（A轮30/B轮20/C轮15/上市12）与"18～24个月现金"等参数需重新标定；ONPV模型假设续费率第5年起80%并保持40年，属自我指涉；关键数字多为作者个人估计——凡引用数字须标注"作者估计"。
- 易混淆的相邻方法论：V10 资本寒冬资源投放优先级（部门级排序，产研排最后）；V08 CAC Payback（人效是压CAC的抓手）；V05 续费率第一指标（长期价值排序）；V03 客单价决定论（客单价带决定组织形态，与人效目标共同约束做法）。
